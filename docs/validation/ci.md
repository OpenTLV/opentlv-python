the initial local checks below were completed on 2026-10-20; the hosted failure
and shell correction are recorded separately for 2026-10-21. Local checks are

## Diagnostics resolved during validation

The locally installed clang-format 21 and an initial clang-format 18 probe
disagreed with two imported expressions. Core's actual pre-commit pin is
23.1.1; using it passed without editing the native sources.

Clang 18 cannot model CPython error-indicator propagation or the scope of
Core's external fixed-format initialization. Cppcheck 2.13 reports two
`Py_RETURN_NONE` branches as missing returns. Reviewed, source-hash-bound
exceptions are documented in
[`static-analysis-baseline.json`](../../cmake/static-analysis-baseline.json).
They fail when the affected source changes and must then be reassessed.

An initial WSL Full run built both wheels but could not bootstrap pip inside
the runtime venv because the local distribution lacks `ensurepip`. The runner
now creates an empty venv and uses the build interpreter's pip `--python`
support to manage it. This keeps the installed-package checks isolated without
changing system Python. The final Windows and Linux runs passed this path.
WSL compilation uses previously extracted local
Python development headers through explicit CMake flags.

## Hosted Full follow-up and shell correction (2026-10-21)

[Full run 39551155012, attempt 1](https://github.com/OpenTLV/opentlv-python/actions/runs/39551155012)
tested commit `42673691c9393e13531debaa744617a2e01afb5f` on `main`.
All ten Linux/Windows configurations passed, as did source quality, CodeQL and
timing collection. All five macOS configurations failed before starting the
Python build runner with `extra[@]: unbound variable`. The quality gate correctly
rejected the failed build prerequisite.

The optional argument array was empty in ordinary Full mode. Bash 3.2 treats
that empty expansion as unset under `set -u`. The correction keeps the whole
command in a nonempty array, appends `--require-release` only when requested,
and preserves strict shell options and build failure propagation through `tee`.
The build and quality-gate steps use the same argument pattern.

Eight regression cases execute the actual workflow scripts with a stub runner,
covering both steps, both release-flag values and success/failure exit codes.
The build matrix runs these checks on every platform before building packages.

Local validation of this correction:

- GNU Bash 3.2.57, built in WSL from the official GNU release archive with its
  parser regenerated by Bison 3.8.2, reproduced the original committed workflow's
  exact failure before runner startup. All eight cases passed with the corrected
  workflow on the same Bash executable.
- Windows/CPython 3.11 with Git Bash: all 129 dependency/public-target/CI
  infrastructure tests passed, including the eight shell regressions.
- WSL Ubuntu/CPython 3.12 with the default system Bash: the same 129 tests passed.
- Python syntax, workflow structure, clang-format 23.1.1, actionlint 1.7.7 and
  `git diff --check` passed. Native package builds/runtime tests were not repeated
  for this shell-only correction.

Logs are retained under ignored `build/issue3-shell-*` paths. The earlier
`ci.json` remains the 2026-10-20 local native-build snapshot.
