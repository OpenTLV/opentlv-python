## [0.1.0] - 2026-10-28

### Changed

- Dispatch `Python release preparation` with a required `tag` input, such as `v0.1.0`, like Core, CLI and Rust. Preflight accepts only a stable `vMAJOR.MINOR.PATCH` tag that matches the version of both distributions, the `docs/release-notes.md` heading and a closed `CHANGELOG.md` section, and rejects a missing tag or one whose tag or GitHub release already exists. The candidate manifest records the requested tag; publication requires the same tag and creates exactly that tag instead of deriving it from the package version. `publish_release`, the main-only dispatch, Core v0.8.0 verification, attestations and the absence of PyPI publication are unchanged. (#44)
- Prepare the first Python release as `0.1.0` for both distributions, independently of Core. Pin Core `v0.8.0` at `345c77acb29266036df5f27d04ce315bb61853cc`, so every build consumes its authenticated release artifacts instead of a pinned Git checkout; the pin adds and removes no public symbols and core coverage stays 213/213 (100.0 %). Release preparation requires versioned release notes in `docs/release-notes.md` and a changelog section closed for the version, both part of the hashed CI definitions. Publication uploads a draft GitHub release with those notes instead of generated ones, checks the tag commit, the notes and every uploaded asset's size and digest, and only then publishes it. The README documents the GitHub CLI requirement and the fourteen examples. PyPI publication remains separate. (#42)
- Normalize Python licensing and community policies to the Workspace reference: `REUSE.toml` annotates documentation, configuration and frozen migration evidence by explicit path, `LICENSES/MIT.txt` supplies the license text, and the source quality check runs `reuse lint` with the pinned REUSE 6.2.0. The contributor guide documents copyright attribution, source headers and packaged license notices; it, the README and the development guide link the shared `OpenTLV/.github` contribution, conduct, security and support policies. (#33)
- `QueryProgram` with static names compiles directly through `tlv_query_compile_scratch()` and `tlv_query_compile()`; a `resolve` callback keeps checked preparation and commit, and both produce the same image. `QueryExecution.reset()` resets in place through `tlv_query_exec_reset()`, keeping its program, providers, workspace and budgets. Document evaluation without `value_capacity` measures the Value snapshot with `tlv_document_query_value_size()` only for programs that read constructed Values, instead of always sizing the whole encoded Document. `Query.visit_buffer()` traverses complete input through `tlv_query_visit_buffer()` without a Reader and takes only `max_depth` and `max_elements` limits. (#22)
- Normalize Python sources under `src/opentlv`, native code under `native`, and standalone tests/examples; update packaging, validation and development paths without changing package identities or API. (#10)
- Clarify standalone installation, workspace development, supported Python versions and contribution ownership, and link examples to the Python repository. (OpenTLV/opentlv-docs#34)
- Report the independent Python binding version through `opentlv.__version__` and `_opentlv.version_string()`, and require the matching native package version. (#4)

### Fixed

- Install the statically linked Core's license into the native wheel from a CMake-style path. The Core selection records a native path, and on Windows its backslashes, such as in `D:\a\...`, became escape sequences in the generated install script. CMake 4 rejects them, so every Windows wheel build failed; a CMake regression test installs the license from a native path containing `\a`. (#42)
- Include license texts in the Python packages: both distributions declare `license-files = ["LICENSE"]`, so wheels and sdists carry `LICENSE` with a `License-File` entry, including the `opentlv` packages that had none (from the `src/LICENSE` copy). The native `opentlv-core` wheel also carries the license of the statically linked Core as `.dist-info/licenses/OpenTLV/LICENSE`, and the package checks reject packages without these texts. The build requires scikit-build-core 0.11 and hatchling 1.27 for PEP 639 license files. (#33)
- Correct the `LICENSE` copyright holder from the OpenTLV organization, inherited from the GitHub template, to Marek Cingel, matching the source headers and the Core license. (#16)
- Fix macOS CI startup with Bash 3.2 while preserving optional verified-Core arguments and failure propagation. (#3)

### Added

- Bind the remaining core API: `ValueConstraint` checks its definition on construction (`tlv_value_constraint_check()`), validates decoded values (`tlv_value_constraint_validate()`) and looks up named numbers (`tlv_value_constraint_name()`). `PackedField.read()` and `write()` extract and insert one bit field of a header integer (`tlv_packed_field_read()`, `tlv_packed_field_write()`), keeping every bit outside the field. `SchemaNumberCodec` is a `NumberCodec` limited by a `LengthRule` through `tlv_schema_number_codec()`: decoding validates the Value length and encoding selects the shortest permitted width. `Document.revision` (`tlv_document_revision()`) counts successful edits and `Node.source_location` (`tlv_node_source_location()`) reports original input coordinates. `Node` checks its handle with Core's never-reused node identity, `tlv_document_retire_epoch()` and `tlv_document_node_identity()` instead of binding-side ownership tokens; an applied Query edit still invalidates every earlier Node. `Decoded.preserve_into()` calls `tlv_source_preserve()` instead of a hand-built `tlv_writer_t` and keeps `required` and `available`. `Query` and `Document.find_path()` parse through `tlv_query_parse_n()` with the text's length, so an embedded NUL raises `InvalidSyntaxError` at its offset instead of `ValueError`. `OpenTLVError.path_text` holds a tracked path formatted by `tlv_diagnostic_path_string()`. The new `audit.py` example combines a named-number check, a packed flag edit and the source location of a changed element. Format and codec callback implementations installed by bound descriptor initializers, and `tlv_query_parse()`, are in the API coverage ignore list with their reasons; core coverage of Core 0.7.1 is 213/213 (100.0 %). (#31)
- Stream through native Reader and Writer sessions: `Writer` appends through one C `tlv_writer_t` over borrowed caller storage or an owned bytearray (`tlv_writer_init()`, `tlv_writer_write_element_diag()`, `tlv_writer_copy_encoded_diag()`, `tlv_writer_preserve_diag()`), and its `position` and `remaining` come from `tlv_writer_size()` and `tlv_writer_remaining()`. Borrowed storage cannot be resized while the Writer exists, and a Format that cannot write is rejected when the Writer is created. Owned growth moves the session to larger storage and C copies the written prefix, so earlier `view()` results stay valid instead of blocking growth. `write_element(storage, element, format, offset=...)` encodes one Element into caller storage through `tlv_write_element_diag()`. `Reader.read_element()` (`tlv_reader_next_diag()`) and `read_element(data)` (`tlv_read_diag()`) decode without building Layout and source metadata, and `read()` decodes once through `tlv_read_source_diag()` instead of opening a Reader. The new `stream.py` example streams into a fixed buffer. Wrappers that pass a NULL diagnostic to a bound `_diag` function, the Tag/Value write forms and `tlv_writer_copy_element()` are in the API coverage ignore list with their reasons; core coverage of Core 0.7.1 is 202/235 (86.0 %). (#29)
- Bind Core's generic Value and structure codecs: `ValueCodec` exposes the `tlv_codec_uint8`, `uint16`/`uint32` big- and little-endian, `int64_minimal_be`, `bytes`, `ipv4` and `ipv4_list` descriptors, with IPv4 lists returned as `IPv4Address` tuples copied through `tlv_ipv4_list_at()`. `TextCodec` binds `tlv_text_*` with its ASCII alphabet, fixed width and zero padding, and `DigitsCodec` binds `tlv_digits_*` digit strings that keep leading zeros. Every Value codec, like `NumberCodec`, offers `decode`, `encode`, `encoded_size` and `encode_into`. `StructureCodec` binds `tlv_structure_decode()`/`tlv_structure_encode()`: C validates a complete sequence against its Format, limits and optional `StructureSchema` or `CheckedStructureSchema` before a Python `decode` callback sees it, and validates the bytes a Python `encode` callback returns before handing them back. `QueryCodecProvider` also accepts the fixed integer codecs, signed for `INT64_MINIMAL_BE`, and `TextCodec` or `ValueCodec.BYTES` for `text`. (#23)
- Reuse checked schemas and compiled Query plans: `StructureSchema.check()` checks a definition once through `tlv_schema_prepare()` and returns a `CheckedStructureSchema` that owns a native copy of the schema graph and validates through `tlv_schema_validate_checked()` and `tlv_schema_validate_all_checked()`; `check_definition()` runs `tlv_schema_check()` alone. `QueryProgram.open_plan()` opens a native plan without the Query frontend (`tlv_query_plan_open()`) and `plan_info` reads a program's requirements from its plan (`tlv_query_plan_info()`). `QueryCodecProvider` decodes `num`, `bcd` or `date` Values with a `NumberCodec` through `tlv_query_codec_decode()`, without Python callbacks. `QueryExecution.visit_document()` visits Document results through `tlv_document_query_program_visit()`, `Document.visit()` visits path matches as nodes through `tlv_document_query_visit()`, and `Query.format()`/`str()` return the canonical path through `tlv_query_format()`. (#22)
- Generate reproducible wire data from Python: `Generator` binds Core's `tlv_generate()` and `tlv_generator_workspace_size()` for any readable and writable Format, including composed ones, from `GeneratorCandidate` identifiers with inclusive Value size intervals, element, depth, Value and case size limits and a seed. `generate(case_index)` returns one complete Writer-reconstructible stream as `bytes`, `generate_into(buffer, case_index)` writes it into caller storage, `workspace_size` reports the scratch size the binding allocates, and `Generator.VERSION` exposes the native algorithm version for corpus metadata. (#21)
- Compose custom Formats without C: `Format.fields()`, `Format.variable()`, `Format.escaped()` and `Format.packed()` build a `ComposedFormat` from `FixedIdentifier`, `VariableIdentifier`, `FixedLength`, `VariableLength`, `EscapedLength` and `PackedField` encodings, with optional tag-only identifiers and `ConstructedBit` nesting, through Core's variable, escaped, packed, binary, tagged and generic field compositions. Composed formats work with Reader, TreeReader, Writer, TreeWriter, Document, Query and schemas; every Format also exposes `decode()`, `measure()`, `encode()`, `can_read` and `can_write` with the Format's error detail. Native entry points take one format specification instead of separate fixed-format variants. (#20)
- Report pinned Core API coverage in PR and Full CI as a non-blocking job: `TLV_API` functions and data referenced from `native/` and `src/`, in total and per header, for core and builtins separately; added and removed symbols when a pull request changes the Core pin; and a documented ignore list for primitives and diagnostic producers in `cmake/api-coverage.json`. The script uses only the standard library and can be reused by other bindings. (#19)
- Optionally publish verified candidates as GitHub releases and notify Docs with exact published-release evidence; keep package-index publication disabled. (OpenTLV/opentlv-docs#42)
- Notify the documentation portal after successful Main CI documentation changes, with exact source identity, isolated dispatch credentials and regression coverage. (#13)
- Add Python package version/Core compatibility policy, validated CI distribution artifacts, and manual release preparation with checksums and provenance; keep publication disabled. (#4)
- Add standalone Python PR, Main, and Full CI with installed-package tests, platform/version coverage, and verified dependency quality gates. (#3)
- Build Python packages independently with pinned Core identity, verified release artifact support, and all supported Core features enabled. (#2)
- Import the existing Python bindings, tests, examples, and documentation from Core with recorded migration provenance and baseline validation. (#1)
